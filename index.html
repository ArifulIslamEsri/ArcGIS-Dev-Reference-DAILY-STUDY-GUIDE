How the SDKs fit together

● MAPS SDK FOR JAVASCRIPT
Core Concepts
The Maps SDK JS is built around a few key objects. Master these and everything else makes sense.
Mental Model
🗺

Map object

Holds layers and a basemap. Has no visual output by itself — it's just the data model. Think of it as a "scene graph".

👁

MapView / SceneView

Takes a Map and renders it into a DOM element. MapView = flat 2D. SceneView = globe/3D. You always need a View.

📦

Layers

FeatureLayer (vector features), TileLayer (raster tiles), GraphicsLayer (custom drawing), ImageryLayer (rasters).

🎨

Renderers & Symbols

Control how features look. SimpleRenderer = one style. UniqueValueRenderer = by category. ClassBreaksRenderer = by value range.

💬

PopupTemplate

Defines what appears when a user clicks a feature. Can include field values, custom HTML, charts, and media.

🔍

Query / FeatureSet

Query lets you filter features by SQL where-clause, geometry, distance. Returns a FeatureSet of matching graphics.

📌 Key pattern Everything in the SDK uses AMD-style ES module imports. You import each class from its own module path: @arcgis/core/Map.js. This allows tree-shaking — only the code you use gets bundled.
● MAPS SDK JS — LAYERS

Layers are how data gets into your map. Pick the right layer type for your data source.
Layer TypeData SourceWhen to Use

TileLayerTile map serviceFast cached raster basemaps, non-interactive backgrounds
VectorTileLayerVector tile serviceStyled basemaps (like Mapbox tiles) — fast and styleable
MapImageLayerMap service (dynamic)Complex multi-layer map services from ArcGIS Server
ImageryLayerImage serviceSatellite/aerial imagery, raster analysis
CSVLayerCSV file URLQuick display of spreadsheet data with lat/lon columns
GeoJSONLayerGeoJSON URL / objectOpen data, GitHub gists, external GeoJSON sources
WFSLayerOGC WFS endpointOpen standards, non-Esri GIS servers

💡 FeatureLayer vs GraphicsLayer FeatureLayer streams from a service and supports server-side queries, rendering, and editing. GraphicsLayer is purely in-memory — great for drawn or calculated shapes, but doesn't persist. For the Sketch widget, always use GraphicsLayer.

● MAPS SDK JS — EXAMPLES
Code Examples
Example 1
minimal-map.js JAVASCRIPT 
// Minimal working map — 12 lines
import Map from "@arcgis/core/Map.js";
import MapView from "@arcgis/core/views/MapView.js";

const map = new Map({ basemap: "streets-vector" });

const view = new MapView({
  container: "viewDiv",  // <div id="viewDiv"> in HTML
  map: map,
  zoom: 10,
  center: [-118.2, 34.0]  // [longitude, latitude]
});
Example 2
add-feature-layer.js JAVASCRIPT 
import FeatureLayer from "@arcgis/core/layers/FeatureLayer.js";

const layer = new FeatureLayer({
  url: "https://services.arcgis.com/.../FeatureServer/0",
  outFields: ["*"],  // return all fields
  popupTemplate: {
    title: "{NAME}",         // {FIELD_NAME} syntax
    content: "{DESCRIPTION}"
  },
  renderer: {
    type: "simple",
    symbol: {
      type: "simple-marker",
      color: "#3b82f6",
      size: 8
    }
  }
});

map.add(layer);  // or: map.layers.add(layer)
Example 3
query-features.js JAVASCRIPT 
// Query features and log attributes
const query = layer.createQuery();
query.where = "POPULATION > 100000";  // SQL WHERE clause
query.geometry = view.extent;          // spatial filter
query.spatialRelationship = "intersects";
query.returnGeometry = true;
query.outFields = ["NAME", "POPULATION"];

const result = await layer.queryFeatures(query);
result.features.forEach(f => {
  console.log(f.attributes.NAME, f.attributes.POPULATION);
});
Example 4
sketch-widget.js JAVASCRIPT 
import GraphicsLayer from "@arcgis/core/layers/GraphicsLayer.js";
import Sketch from "@arcgis/core/widgets/Sketch.js";

const sketchLayer = new GraphicsLayer();
map.add(sketchLayer);

const sketch = new Sketch({
  layer: sketchLayer,
  view: view,
  creationMode: "update"
});
view.ui.add(sketch, "top-right");

sketch.on("create", (event) => {
  if (event.state === "complete") {
    console.log("Drawn geometry:", event.graphic.geometry);
  }
});
● EXPERIENCE BUILDER DEV EDITION
Core Concepts
ExB Dev Edition = ArcGIS Experience Builder + the ability to write custom React widgets using the Jimu framework.

What ExB gives you

  • Drag-and-drop web app builder
  • Connects to ArcGIS Online / Enterprise
  • Built-in widgets: Map, List, Table, Chart...
  • Data linking between widgets
  • No-code layout builder

What Dev Edition adds

  • Write custom React widgets
  • Access the Jimu (吉mu) framework
  • Use JimuMapView to control maps
  • Connect custom widget to data sources
  • Hot reload dev server
Key Concepts
🧩

Widget

A React component in your-widget/src/runtime/widget.tsx. Receives props from ExB including data sources and map.

⚙️

Setting panel

The config UI shown when an author edits the widget in ExB builder. Defined in setting/setting.tsx.

🗄

Data source

Connection to a feature service or table. Use useDataSource in manifest to declare, then DataSourceComponent to consume.

🗺

JimuMapView

The ExB wrapper around a MapView. Get it via JimuMapViewComponent to access the underlying ArcGIS MapView.

📋

manifest.json

Declares widget metadata, dependencies, use maps, use data sources. ExB reads this to wire your widget into the builder.

🔗

Message / Action

Widgets communicate via the message framework — one widget publishes, another subscribes. No direct component coupling.

⚠️ Jimu ≠ standard React ExB uses the "Jimu" framework on top of React. Don't use useState for settings — use props.config and props.onSettingChange. Widget state is managed by ExB's Redux store.
Widget folder structure
custom-widget/ folder layout STRUCTURE 
your-widget/
├── manifest.json       ← metadata, deps, config shape
├── src/

● EXPERIENCE BUILDER — CUSTOM WIDGET
Building a Custom Widget
  1. Install ExB Dev Edition — Download from My Esri. Node.js 16+ required. Run npm ci in the ExB folder then npm start.
  2. Create widget folder — Place your widget in client/your-extensions/widgets/my-widget/
  3. Write manifest.json — Declare the widget name, version, dependencies (use maps, data sources).
  4. Build widget.tsx — Export a React component as default. Receives AllWidgetProps from Jimu.
  5. Build setting.tsx — Optional config panel. Use Jimu UI components (Button, TextInput, etc).
  6. Hot reload — Save files, ExB dev server reloads automatically. Open localhost:3001 to test.
  7. Deploy — Copy your widget folder into the production ExB widgets/ folder.
🎯 Pro tip — use JimuMapViewComponent To interact with the map from your widget, add useMapWidgetIds to manifest.json, then use <JimuMapViewComponent onActiveViewChange={...}> in widget.tsx. The callback gives you the live ArcGIS MapView instance.
● EXB DEV EDITION — EXAMPLES
Code Examples
manifest.json
manifest.json JSON 
{
  "name": "my-custom-widget",
  "label": "My Widget",
  "version": "1.0.0",
  "jimuVersion": ">=1.0.0",
  "properties": {},
  "dependencies": ["jimu-core", "jimu-arcgis"],
  "useMapWidgetIds": true,     // enables JimuMapViewComponent
  "useDataSources": [{           // connect a data source
    "types": ["FEATURE_LAYER"]
  }]
}
widget.tsx — map interaction
src/runtime/widget.tsx TSX 
import { React, AllWidgetProps } from "jimu-core";
import { JimuMapViewComponent, JimuMapView } from "jimu-arcgis";

export default function Widget(props: AllWidgetProps<any>) {
  const [mapView, setMapView] = React.useState<JimuMapView>(null);

  const handleViewChange = (jmv: JimuMapView) => {
    setMapView(jmv);
    // jmv.view is the actual ArcGIS MapView
    console.log("Map ready:", jmv.view);
  };

  const zoomToLA = () => {
    if (!mapView) return;
    mapView.view.goTo({ center: [-118.2, 34], zoom: 12 });
  };

  return (
    <div>
      <JimuMapViewComponent
        useMapWidgetId={props.useMapWidgetIds?.[0]}
        onActiveViewChange={handleViewChange}
      />
      <button onClick={zoomToLA}>Zoom to LA</button>
    </div>
  );
}
● ARCGIS PRO SDK FOR .NET
Core Concepts
The Pro SDK lets you write C# add-ins that run inside ArcGIS Pro. Think of it like a plugin system — your code lives inside the Pro process.

What you can build

  • Custom buttons in the Pro ribbon
  • Dockable panes (custom panels)
  • Map tools (click/drag interactions)
  • Geoprocessing tool wrappers
  • Custom sketch tools

Key requirement

  • Windows only (ArcGIS Pro is Windows)
  • C# / VB.NET + Visual Studio
  • Pro SDK NuGet package
  • .NET 6+ (Pro 3.x)
  • ArcGIS Pro installed
🔌

Add-in

A .esriAddinX file deployed to ArcGIS Pro. Contains all your custom buttons, panes, and tools. Registered via config.daml.

📄

config.daml

XML manifest for the add-in. Declares buttons, menus, panes, conditions, and where they appear in the Pro UI (ribbon groups).

⚡

MCT (Main CIM Thread)

Pro uses a strict threading model. All map/layer access MUST run on the MCT via QueuedTask.Run().

🗺

MapView

The Pro equivalent of a map display. Access via MapView.Active. Not the same as JS SDK's MapView.

🔧

MapTool

Base class for custom map interactions. Override OnSketchCompleteAsync to handle drawn geometry.

📊

CIM (Cartographic Info Model)

The JSON-like model behind Pro's symbols, renderers, and layouts. You can get/set CIM directly for advanced customization.

⚠️ Threading is critical in Pro SDK Never access map layers or geodatabases on a background thread. Always wrap operations in await QueuedTask.Run(() => { ... }). Breaking this causes cryptic exceptions.
● PRO SDK — EXAMPLES
Code Examples
Button add-in — select features in extent
SelectByExtentButton.cs C# 
using ArcGIS.Desktop.Framework.Contracts;
using ArcGIS.Desktop.Mapping;
using ArcGIS.Desktop.Framework.Threading.Tasks;

internal class SelectByExtentButton : Button
{
  protected override async void OnClick()
  {
    // Always use QueuedTask for map access
    await QueuedTask.Run(() =>
    {
      var mapView = MapView.Active;
      if (mapView == null) return;

      // Get current map extent
      var extent = mapView.Extent;

      // Select features in the extent
      mapView.Map.SelectByRectangle(
        mapView,
        extent.ToEnvelope(),
        SelectionCombinationMethod.New
      );
    });
  }
}
Custom map tool — click to get coordinates
CoordinateClickTool.cs C# 
internal class CoordinateClickTool : MapTool
{
  public CoordinateClickTool()
  {
    IsSketchTool = true;
    SketchType = SketchGeometryType.Point;
  }

  protected override Task<bool> OnSketchCompleteAsync(
    Geometry geometry)
  {
    return QueuedTask.Run(() =>
    {
      var point = geometry as MapPoint;
      var msg = $"X: {point.X:F4}, Y: {point.Y:F4}";
      ArcGIS.Desktop.Framework.Dialogs.MessageBox
        .Show(msg, "Clicked Point");
      return true;
    });
  }
}

● ARCGIS ENTERPRISE SDK
Core Concepts
The Enterprise SDK lets you extend ArcGIS Server — adding custom REST endpoints (SOE) or intercepting existing ones (SOI). Runs server-side, not in the browser.
🔌

SOE (Server Object Extension)

Adds custom REST operations to an existing service. Clients call /exts/MySOE/customOp. Best for adding new business logic endpoints.

🚧

SOI (Server Object Interceptor)

Intercepts all requests to a service before they're processed. Use for custom auth, logging, request filtering, or modifying responses.

📦

.soe file

The compiled output — a JAR (Java) or DLL (.NET) wrapped in a .soe package. Registered in ArcGIS Server Manager under Extensions.

🔒

IServerObjectExtension

The main interface to implement. Includes Init(), Shutdown(), and for SOE, HandleRESTRequest().

🌐

REST capabilities

Your SOE declares its operations in JSON. Each operation has a name, parameters, and a return type. ArcGIS Server auto-generates the REST endpoint docs.

📝

Geodatabase access

SOEs can access feature classes, tables, and workspaces server-side via the ArcObjects / ArcGIS Engine API behind the scenes.

⚠️ Enterprise SDK is advanced This SDK requires deep ArcGIS Server knowledge, Java or .NET, and deployment to a live server. Mistakes can break services for all users. Test in a dev environment first.
● ENTERPRISE SDK — EXAMPLES
Code Examples
SOE skeleton — Java
MyCustomSOE.java JAVA 
import com.esri.arcgis.server.json.*;
import com.esri.arcgis.interop.AutomationException;

public class MyCustomSOE
  implements IServerObjectExtension,
             IRESTRequestHandler
{
  private IServerObjectHelper soHelper;

  public void init(IServerObjectHelper soh) throws Exception {
    this.soHelper = soh;
    // init geodatabase connections, caches, etc.
  }

  public void shutdown() throws Exception {
    // release resources
  }

  public byte[] handleRESTRequest(
    String capabilities, String resourceName,
    String operationName, String operationInput,
    String outputFormat, String requestProperties,
    String[] responseProperties) throws Exception
  {
    if (operationName.equalsIgnoreCase("getStats")) {
      return handleGetStats(operationInput);
    }
    return new JSONObject().put("error", "Unknown operation")
      .toString().getBytes("UTF-8");
  }

  private byte[] handleGetStats(String input) throws Exception {
    JSONObject result = new JSONObject();
    result.put("featureCount", 1234);
    result.put("status", "ok");
    return result.toString().getBytes("UTF-8");
  }
}
● CLAUDE'S PERSPECTIVE
Insights & Pro Tips
Things I'd tell a developer starting out with ArcGIS SDKs that the official docs don't always say clearly.
🧭 Start with the right SDK The #1 mistake is starting with ExB Dev Edition thinking it's simpler. It's not — you're writing React inside a proprietary framework. If you know web dev, Maps SDK JS is far more approachable. ExB is best if your org is already on ArcGIS Online/Enterprise and you're extending existing apps.
💡 Maps SDK JS: AMD vs ES modules The SDK supports two loading patterns. CDN (via <script> tag) uses AMD. npm uses ES modules. They look different but do the same thing. For new projects always use npm + ES modules — you get TypeScript types, tree-shaking, and bundler support.
📌 The View is async — use .when() view.when() returns a Promise that resolves when the map is ready. Always wait for it before querying layers or zooming programmatically. await view.when() is the correct pattern.
⚠️ Pro SDK: the MCT threading rule will break you ArcGIS Pro enforces a strict threading model. When you get a CalledOnWrongThreadException, it means you touched map data outside QueuedTask.Run(). This is by far the most common Pro SDK frustration — memorize this pattern early.
💡 FeatureLayer: use definitionExpression for performance Instead of querying and filtering client-side, set layer.definitionExpression = "STATUS = 'ACTIVE'" — this filters server-side and only streams matching features to the browser. Massive performance gain on large datasets.
🎯 Enterprise SDK: SOE vs SOI decision Ask: do you need to ADD new functionality (new endpoint)? → SOE. Do you need to INTERCEPT or MODIFY existing behavior (auth, logging, transform output)? → SOI. Many teams use both: SOI for auth/logging, SOE for business logic endpoints.
📌 ExB: don't fight Jimu's data model Jimu manages widget state and data flow via its own Redux store. Don't use localStorage or global variables to pass data between widgets. Use the Message/Action framework — it's verbose but it's the correct pattern, and it makes your widget work in published apps.
💡 Use the ArcGIS Playground developers.arcgis.com/javascript/latest/sample-code/ has 400+ live samples. The fastest way to learn is to fork a sample close to what you need rather than building from scratch.
🎯 Learn these 5 things first for JS SDK (1) Map + MapView basics. (2) FeatureLayer + popupTemplate. (3) Query / queryFeatures. (4) view.on("click", ...) for interactivity. (5) view.ui.add() for widgets. Everything else builds on these.
